# F04 · 知识地图（主页）

> 用户打开 app 看到的第一屏。不是任务清单，是**当前知识状态的可视化 + 入口选择**。

## Why

主页是产品的「心智设定」。多邻国的主页是「关卡列表」——决定了用户的心智是「完成下一关」。Fast Memory 的主页是「知识地图」——决定了用户的心智是「探索 + 巩固」。

这一屏直接体现 [`../00-vision/design-principles.md`](../00-vision/design-principles.md) 的**原则 1（状态 > 任务）** 和**原则 3（网络 > 线性）**。

---

## 用户行为

打开主页时，用户能做的：

1. **扫一眼自己的整体状态**（哪些区域已掌握、哪些衰减中、哪些未学）
2. **决定做什么**（4 个入口，用户自己选）
3. **跳到任一节点**（点击任意已学/未学节点）
4. **搜索**（顶部搜索框）

用户**不需要**做的：
- 不需要完成"今日目标"
- 不需要按推荐顺序学
- 不需要看完整张地图

## 关键设计决策

### 1. "想做点什么？" 而不是 "今天的任务"

四个入口，**用户主导**：

| 入口 | 触发条件 | 不出现条件 |
|---|---|---|
| 🔁 补强衰减中的 | 至少 1 个节点 mastery_tier = fading | 无衰减节点 |
| 🆕 探索新节点 | 总有可推荐的（基于已学的相邻节点） | 完成全部时（不太可能） |
| ↩ 继续上次 | 有未完成的测试会话 | 上次完整结束 |
| 🗺 自由浏览 | 总是显示 | — |

**文案**：用「想做点什么？」（问句、提议），不用「今日推荐」（陈述、暗示责任）。

### 2. 状态概览数据

4 档分布的横向条形图。视觉上能 5 秒内看出：
- 总进度多少
- 衰减中有几个（这是真正需要关注的状态）

**不显示**：完成度百分比、连续学习天数、累计时长。

### 3. 大纲树 = 知识地图

层级展开的列表：
- L1/L2 大类作为顶层
- 每个节点旁显示状态符号 + 总进度（X/Y）
- 默认折叠，用户展开自己关心的部分
- 整张图状态会被本地缓存，再次打开瞬间渲染

**为什么不画真正的图谱**：
- MVP 阶段视觉化是增量（原则 6）
- 大纲树本身就能表达层级和状态
- 图谱可视化复杂度高（D3 力导向布局）、移动端难用
- 用户的真实导航需求 80% 是"找到某个节点"，不是"看全图"

将来可以加图谱视图作为 F08 之类的辅助功能。

### 4. 搜索

顶部搜索框（FlexSearch 客户端实现）。匹配：
- 节点 title
- 节点 summary
- 节点 body 内容
- 题目 stem

返回结果按相关度 + 用户掌握度（未学优先）排序。

## 状态可视化规则

地图上的状态显示有两个形态：

### 大纲树行末：StatusBar 横向条

每个节点行末显示一个 StatusBar——长度=强度、颜色=档位、衰减附 ▼。

| 状态 | 视觉 | 颜色（变体 A） |
|---|---|---|
| 未学 | `┄┄┄┄┄┄┄┄` 空条 | 灰 `#aea798` |
| 学过 | `■■■■■■░░░░` | 黛青 `#436b80` |
| 熟练 | `■■■■■■■■■›` | 松绿 `#5f7c4d` |
| 衰减中 | `■■■■░░░░░░ ▼` | 赭石 `#a06d2e` |

### 分类总进度：DistributionBar

每个分类（如"阴阳五行"）显示一个**分布条形**——把 4 档比例堆叠在一根横条上：

```
[████░░░░░░░░░░░░]  熟练 4 · 学过 0 · 衰减 0 · 未学 1
```

数字部分给具体数量，便于扫读。

### 颜色梯度逻辑

熟练度从低到高：未学（灰）→ 衰减（赭石）→ 学过（黛青）→ 熟练（松绿）。

衰减用暖色（赭石）警示但不刺激，区别于"错误红"。

完整组件实现见 [`/design/tokens.jsx`](../../design/tokens.jsx) 的 `StatusBar` 和 [`/design/design-system.jsx`](../../design/design-system.jsx) 的 `DistributionBar`。

## 数据依赖

读：
- `content/.build/graph.json` → 所有节点 + 分类结构
- `user_node_progress` for 当前用户 → 所有节点的 mastery_tier
- `user_sessions` 最后一次未完成的会话 → "继续上次"
- `getRecommendedReview(user)` → 「补强」入口的节点列表
- `getRecommendedNew(user)` → 「探索新节点」推荐

写：
- 仅用户行为日志（点击哪个入口、展开哪个分类）

## "探索新节点" 推荐算法

```typescript
function recommendNewNode(userId: string): NodeId | null {
  const progress = loadUserProgress(userId);
  const learnedNodes = progress.filter(p => p.visit_count > 0).map(p => p.nodeId);

  // 找已学节点的「相邻未学节点」（图距离 = 1）
  const candidates = new Set<NodeId>();
  for (const learnedId of learnedNodes) {
    const neighbors = getRelations(learnedId).map(r => r.target);
    for (const n of neighbors) {
      if (!learnedNodes.includes(n)) candidates.add(n);
    }
  }

  // 按距离用户兴趣的相关度排序（最近学的节点的邻居优先）
  const sorted = Array.from(candidates).sort(byRecencyOfLearnedNeighbor);
  return sorted[0] ?? pickStarterNode();  // 兜底：L1 公理节点
}
```

如果用户完全没学过：推荐 L1 节点（阴阳 / 整体观）。

## 验收标准

MVP：

- [ ] 状态概览：4 档横向条形图
- [ ] "想做点什么？" 4 个入口（按条件出现/隐藏）
- [ ] 大纲树：所有节点按层级 + 分类展开/折叠
- [ ] 每个节点显示状态符号 + 颜色
- [ ] 点击任一节点 → 跳到 F01 节点页
- [ ] 顶部搜索（节点 title + summary）
- [ ] 推荐算法：相邻未学节点

MVP+：

- [ ] 搜索覆盖 body 全文
- [ ] 搜索结果中标记状态
- [ ] 大纲树状态本地缓存（再次打开瞬间渲染）

非 MVP：

- [ ] 图谱视图（力导向布局）
- [ ] 自定义分组 / 收藏夹
- [ ] 学习历史时间线

## 反模式

- ❌ 不显示"连续学习 N 天"
- ❌ 不显示"今日已学习 N 分钟"
- ❌ 不显示"完成度 X%"（违反原则 1）
- ❌ 不要"今日任务"模块（违反原则 1）
- ❌ 不要主动 push 弹窗（违反原则 2）
- ❌ 不要排行榜 / 好友进度（违反原则 5）

---

## 设计依据

- **原则 1（状态 > 任务）**：所有数字都是状态描述，没有"任务"语义
- **原则 2（行为驱动）**：没有时间词，用户随时回来都看到当下状态
- **原则 3（网络 > 线性）**：用户可从任一节点切入，4 个入口全是用户自选
- **原则 5（工具 > 游戏）**：无 streak、徽章、对比

## Open Questions

- [ ] "继续上次" 在用户上次正常完成后还要显示吗？倾向于隐藏（已经结束就不是"继续"了）。
- [ ] 大纲树默认折叠还是默认展开？倾向于「已经有进度的展开，未学的折叠」。
- [ ] 搜索结果是否需要分组（节点 / 题目）？倾向于一开始合并显示，类型用标签区分。
