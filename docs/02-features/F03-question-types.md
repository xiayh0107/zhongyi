# F03 · 题型系统

> 7 种题型，覆盖从识别到推导的不同认知层级。多题型混合是为了**避免「我只是认识，但说不出」的流畅性错觉**。

## Why

只用单选题刷题，用户会形成「能在 5 个选项里挑出正确答案 ≠ 能从脑子里调出来」的错觉。多题型迫使大脑用不同方式提取同一信息，建立更牢固的索引。

每种题型对应一种认知层级：

| 题型 | 认知层级 | 例 |
|---|---|---|
| single_choice | 识别 | "肝在志为？" + 5 选项 |
| multiple_choice | 集合识别 | "津液代谢相关脏腑有？" |
| fill_in_blank | 主动调取 | "心其华在 ___" |
| match | 关系识别 | 5 脏 ↔ 5 在液 |
| sort | 顺序记忆 | 十二经脉流注顺序 |
| spell | 精确回忆 | 输入"足三里" |
| derive | 推导 | "基于五行推肺与脾的关系" |
| blank_recall | 完整召回 | "列出脾的所有功能"（详见 F05） |

## 各题型详解

### 1. single_choice（单选）

**数据**：
```yaml
type: single_choice
stem: 肝在志为？
options: [喜, 怒, 思, 悲, 恐]
answer: 1
```

**UI**：
```
┌──────────────────────────────────────┐
│ 肝在志为？                            │
│                                      │
│  ○ 喜                                │
│  ○ 怒                                │
│  ○ 思                                │
│  ○ 悲                                │
│  ○ 恐                                │
│                                      │
│  [ 提交 ]              [ 跳过 ]      │
└──────────────────────────────────────┘
```

**反馈**：
- 答对：选项变绿 + ✓ + 提交按钮变「下一题」
- 答错：选中项红色 + 正确项绿色 + 显示 Why 卡片
- 始终有 [Why?] 按钮可点开详解

### 2. multiple_choice（多选）

**数据**：
```yaml
type: multiple_choice
stem: 津液代谢相关的脏腑包括（多选）：
options: [肺, 脾, 肾, 肝, 三焦, 心]
answer: [0, 1, 2, 3, 4]
```

**UI**：复选框 + 「确认选择」按钮（不要选中即提交）

**反馈**：
- 漏选：未选的正确项标橙色 "应选"
- 多选：错选项标红色 "不应选"
- 全对：全部绿色

### 3. fill_in_blank（填空）

**数据**：
```yaml
type: fill_in_blank
stem: 心其华在 ___
answer: [面, 面部]    # 允许多种写法
```

**UI**：
```
心其华在 [_____] 。

    [ 提交 ]   [ 看提示 ]
```

**反馈**：
- 精确匹配 / 容错匹配 → 答对
- 模糊匹配（编辑距离 ≤ 1）→ 提示「接近，正确答案是 X」，按 Hard 算
- 提示功能：显示首字 / 字数

### 4. match（匹配）

**数据**：
```yaml
type: match
options:
  left: [心, 肝, 脾, 肺, 肾]
  right: [筋, 肌肉, 皮, 骨, 脉]
answer: [[0,4],[1,0],[2,1],[3,2],[4,3]]
```

**UI**：
```
左侧拖拽到右侧 / 点击连线：

  心 ────┐        ┌──── 筋
  肝     │        │
  脾     ├────────┤     肌肉
  肺     │        │     皮
  肾 ────┘        └──── 骨
                       脉
```

**反馈**：
- 提交前可调整
- 错误的连线标红，正确的标绿

### 5. sort（排序）

**数据**：
```yaml
type: sort
stem: 把以下十二经脉按流注顺序排列（从手太阴肺经开始）：
options: [足太阴脾经, 手太阴肺经, 手阳明大肠经, 足阳明胃经, ...]
answer: [1, 2, 3, 0, ...]    # 选项中的正确顺序索引
```

**UI**：拖拽排序的卡片列表

**反馈**：每个位置 ✓ / ✗

### 6. spell（拼写）

**数据**：
```yaml
type: spell
stem: 该穴位的标准名称是？（位置：腕掌侧远端横纹上 3 寸，掌长肌腱与桡侧腕屈肌腱之间）
answer: [内关, 内关穴]
```

**UI**：
```
该穴位的标准名称是？

    [_______________]

    [ 提交 ]   [ 看提示 ]
```

**反馈**：精确匹配 / 容错（错别字提示）

### 7. derive（推导）

**数据**：
```yaml
type: derive
stem: 基于五行学说，解释为什么"肺虚累及脾"。
answer:
  keywords: [土生金, 子病及母, 培土生金]
  min_match: 1
```

**UI**：
```
基于五行学说，解释为什么"肺虚累及脾"。

  ┌────────────────────────────────────┐
  │                                    │
  │  （在此输入你的回答）                │
  │                                    │
  │                                    │
  └────────────────────────────────────┘

    [ 提交 ]   [ 我自评 ]
```

**反馈**：
- 关键词命中率 ≥ min_match → 系统判对
- 否则显示参考答案 + 让用户自评（Hard / Good）
- 始终显示完整解析

### 8. blank_recall（白纸召回）

→ 详见 [F05 白纸召回](F05-active-recall.md)

## 题目流（用户路径）

从节点页「测试自己」进入：

```
┌─────────────────────────────────────────┐
│ 测试：肝   1 / 5                     ✕   │ ← 进度，可退出
├─────────────────────────────────────────┤
│                                         │
│   [当前题目内容]                         │
│                                         │
├─────────────────────────────────────────┤
│   ⏱  本题用时 8s                         │ ← 计时（用于 Rating）
└─────────────────────────────────────────┘
```

完成时：

```
┌─────────────────────────────────────────┐
│ 测试完成                                 │
│                                         │
│ 答对 4 / 5                              │
│                                         │
│ 「肝」的记忆强度：72 → 81 ↑              │ ← 状态变化
│                                         │
│ 错题：                                   │
│ • 肝郁气滞的代表方？ [复习]              │
│                                         │
│ [ 回到节点页 ]   [ 继续做 5 题 ]         │
└─────────────────────────────────────────┘
```

## 题型混合策略

一次测试 N 题如何选题型？

```typescript
function pickQuestions(nodeId: string, n: number): Question[] {
  const all = getQuestionsForNode(nodeId);

  // 按记忆强度排序：强度低的优先
  const sorted = all.sort((a, b) =>
    getCardStrength(a) - getCardStrength(b)
  );

  // 多样化题型：尽量让 N 题覆盖多种类型
  return diversifyByType(sorted, n);
}
```

**约束**：
- 同一节点不能连续 3 题用同一种题型
- 每次至少包含 1 种「主动调取」类型（fill_in_blank/spell/derive/blank_recall）

## 即时反馈规则

**所有反馈必须在 100ms 内出现**（本地计算，无网络依赖）。

反馈三件套：
1. **正确性**：颜色 + 图标
2. **正确答案**：错时显示
3. **Why**：可点击展开

**Why 卡片**：
```
为什么是「怒」？

肝五行属木，木性条达，怒则气上，
故怒为肝之志。

详见：[[肝]]、[[五行学说]]
```

## 验收标准

MVP（必须）：

- [ ] 7 种题型中至少实现 4 种：single_choice, multiple_choice, fill_in_blank, match
- [ ] 反馈延迟 < 100ms
- [ ] Why 按钮工作（始终可点）
- [ ] 答题时间记录精确到秒
- [ ] 完成测试后显示强度变化
- [ ] 错题可点击「复习」（再做一次）
- [ ] 测试中途退出，进度保留（下次进入提示「继续上次」）

MVP+：

- [ ] 实现 sort、spell
- [ ] 题型混合算法（避免连续同类型）

非 MVP：

- [ ] derive 题（需要 LLM 辅助评分）
- [ ] blank_recall（属 F05）

---

## 反模式

- ❌ 答题完成不显示"得了 N 分"的分数——这是任务式，违反原则 1。显示「强度从 X → Y」是状态式。
- ❌ 不要倒计时压力（"剩余 30 秒"）——制造焦虑，无学习价值。计时是为内部 Rating 用。
- ❌ 不显示「击败 X% 用户」——社交压力，违反原则 5。
- ❌ 不强制连续做题——用户可随时退出，进度保留。
