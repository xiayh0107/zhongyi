# F01 · 节点页

> 单个学习概念的核心页面。用户大部分时间花在这里。所有其他功能都围绕节点页展开。

## Why

节点是产品的**最小学习单位**。一个用户的完整学习闭环 ＝「打开节点 → 看讲解 → 主动检索 → 看到强度变化」。这个闭环必须在节点页内完成，不能跳出。

节点页是 F01，编号最小，是因为：
- 所有其他功能都依赖它存在
- 它的设计决定了内容怎么组织、UI 怎么布局、用户怎么思考

---

## 用户行为

进入节点页时，用户能做的事按优先级：

1. **理解这个概念**——读模板表 + 讲解 body
2. **测试自己**——点按钮进入题目流（F03）
3. **跳到相关节点**——双向链接 / 模板字段中的概念
4. **看到自己的状态**——当前记忆强度、上次访问、答题历史
5. **回到知识地图**——面包屑导航

用户**不需要**做的事：
- 不需要登录才能看节点（内容公开，进度需登录）
- 不需要先学前置节点才能进入（网络化原则）
- 不需要"完成"什么——可以随时离开

### 状态可视化（标题右侧）

| 状态 | 符号 | 颜色 | 含义 |
|---|---|---|---|
| 未学 | ○ | 灰 | 从未访问 |
| 学过 | ● | 蓝 | 访问过且强度 ≥ 60 |
| 熟练 | ● | 绿 | 强度 ≥ 85 + 3 次成功检索 |
| 衰减中 | ● ⚠ | 橙 | 曾达到 学过/熟练，但强度 < 60 |

颜色 + 形状双重编码，色盲友好。

### 面包屑导航

- 始终显示路径
- 点击任一段返回对应层
- 路径基于节点的 `category` + `layer` 自动生成

### 主 CTA：测试自己

- 总在视线内（标题旁，桌面端固定；移动端置底）
- 显示挂载到该节点的题目数
- 点击进入题目流（详见 [F03](F03-question-types.md)）

## 数据依赖

读取：
- `content/nodes/{id}.md` → frontmatter + body
- `content/.build/graph.json` → 该节点的所有 relations（前置/并列/关系/延伸）
- `user_node_progress where user_id=? and node_id=?` → memory_strength, mastery_tier
- `content/questions.json` → 挂载到该节点的题目（仅取数量）

写入（用户访问时）：
- `user_node_progress.first_visited` (if null)
- `user_node_progress.visit_count += 1`
- `user_sessions` 记录该节点访问

详见 [`../01-architecture/data-model.md`](../01-architecture/data-model.md)。

## 双向链接处理

构建期：
- 解析 body 中的 `[[node-id]]`
- 校验目标存在，否则构建失败
- 建立反向索引："被哪些节点引用"

运行期：
- `[[node-id]]` 渲染为链接
- 鼠标 hover 显示目标节点的 summary（小卡片）
- 点击跳转 + 触发 visit

---

## 渲染优先级

服务端预渲染（首屏）：
- 面包屑、标题、summary、template 表、body 主体
- 不依赖用户状态，所有用户相同 → 可静态缓存

客户端补充：
- 状态符号（依赖用户进度）
- 「测试自己」按钮的题目计数（其实可以预渲染）
- 相关节点的 ○/● 状态标记

→ 首屏 TTI < 1.5s 应该容易达到。

## 验收标准

MVP 阶段：

- [ ] 任意节点 URL 直达可用（`/nodes/{id}`）
- [ ] 渲染 frontmatter 中的所有 template 字段为表格
- [ ] 渲染 body 的 Markdown（含 `[[wiki-link]]`）
- [ ] 显示用户当前 memory_strength（数值 + 状态符号）
- [ ] 显示挂载题目数
- [ ] 「测试自己」按钮可点击并进入 F03 题目流
- [ ] 双向链接可点击跳转
- [ ] 相关节点列表按"前置/并列/关系/延伸"分组
- [ ] 面包屑导航工作
- [ ] 首次访问写入 first_visited
- [ ] 每次访问 visit_count += 1
- [ ] 未登录用户能看到内容，只看不到状态/题目

非 MVP：

- [ ] hover 节点链接显示 summary 卡片
- [ ] 节点页支持深链锚点（`/nodes/liver#主疏泄`）
- [ ] 节点页支持「上次中断处恢复」（如果在做题中途离开）

---

## 反模式（不做什么）

- ❌ 不显示「学习进度条」「完成度 X%」——节点没有"完成"概念
- ❌ 不显示「估计学习时间 N 分钟」——预设节奏，违反原则 2
- ❌ 不显示「难度等级」——已经有 difficulty 字段在题目层，节点层不需要
- ❌ 不要"下一节点"按钮——这是关卡式，违反原则 3
- ❌ 不要在节点页推送其他用户的统计（"80% 的用户都学过这个"）——社交压力

---

## 设计依据（引用原则）

- 原则 1（状态 > 任务）：标题旁显示强度数值 + 颜色，不显示"该复习"
- 原则 3（网络 > 线性）：相关节点分 4 类显式列出，没有"下一节点"
- 原则 4（主动检索 > 被动阅读）：「测试自己」按钮始终可见、显眼
- 原则 6（视觉化是增量）：MVP 纯文字 + 表格，模板表是结构化文字而非装饰

## Open Questions

- [ ] body 中的章节是否需要支持「折叠/展开」？长节点页可能需要，但折叠会让用户略过——和原则 4 冲突。倾向于默认展开。
- [ ] 是否支持「相关节点」自定义排序？（让用户拖拽）—— 太重，先按算法（学习度优先）排序。
- [ ] 节点页 URL 是否带 slug 还是 ID？（`/nodes/liver` vs `/nodes/n-001`）—— 倾向于 slug（人类可读、SEO）。
