## 产品定位（30 秒理解）

**Fast Memory 是把碎片资料重构为可点亮知识网络的快速学习 Web App。**

首个内容域：**中医学考试资料**（应试者优先）。

我们做的是**工具**，不是习惯机器。

- 多邻国：哄你坐下，让你每天回来 → 我们：尊重你的节奏，需要时打开
- Anki：科学但工程师审美 → 我们：科学 + 美感平衡
- 学而思/猿辅导：题海 + 视频 → 我们：网络化结构 + 主动检索

## 6 条设计原则（速查）

| 原则 | 一句话 | 怎么测试 |
|---|---|---|
| 1. 状态 > 任务 | 呈现"现在系统什么状态"，不是"你该做什么" | 给陌生人看文案，他觉得是"事实"还是"压力"？ |
| 2. 行为驱动 > 预设节奏 | app 节奏来自用户行为，不由开发者预设 | 去掉所有"今天/明天/连续"等时间词，还能工作吗？ |
| 3. 网络 > 线性 | 知识是网络，不是关卡 | 随机选节点能直接进入吗？ |
| 4. 主动检索 > 被动阅读 | 用户产生回答 > 看屏幕字 | 用户读了多少 vs 主动回答了多少？ |
| 5. 工具 > 游戏 | 没有 streak/徽章/等级/排行 | 去掉这个元素，信息更清楚还是少了点什么？ |
| 6. 视觉化是增量 | 先文字，视觉是放大器 | 去掉这张图，记忆效果会变差吗？变多少？ |

完整论证在 [`../00-vision/design-principles.md`](../00-vision/design-principles.md)。

## ⛔ 反模式清单（设计师必读）

**这些 UI 模式被明确禁止，不需要讨论。** 出现在设计稿里会被打回。

### 不要做的 UI 元素

- ❌ **Daily streak / 连续打卡** 🔥 火苗、X 天连续标志
- ❌ **每日学习目标** "今日完成 X / Y"
- ❌ **完成度百分比** "整体进度 73%"（暗示有终点）
- ❌ **Due date / 到期/逾期** "应于昨日复习"
- ❌ **倒计时压力** 答题时的剩余秒数倒数
- ❌ **徽章/勋章/等级/段位/经验值**
- ❌ **排行榜 / 好友进度对比**
- ❌ **"超过 X% 用户"** 社交比较
- ❌ **打分系统** 答题后的"得了 N 分"
- ❌ **皮肤/装饰/盲盒/抽卡**
- ❌ **Push 通知催回** "你 3 天没学了！"
- ❌ **"下一节点"按钮** 暗示关卡序列

### 不要用的文案

| ❌ 别写 | ✅ 这样写 |
|---|---|
| "今日复习 12 张" | "10 个节点强度偏低" |
| "你的今日目标" | "想做点什么？" |
| "完成今日任务" | （没有这个概念） |
| "已逾期 3 天" | "强度: 42 ⚠ 衰减中" |
| "连续学习 7 天 🔥" | "已掌握 32 个节点" |
| "下一关" / "下一节点" | "相关节点：[[X]] [[Y]]" |
| "恭喜！再接再厉！" | "肝 的强度：72 → 81 ↑" |

**核心判断**：UI 文案如果让人感觉"被催"、"被哄"、"被评判"，就违反了原则。

## 视觉风格方向

> 这部分是设计师**主导决策**的，简报只给方向不给约束。

### 总基调

- **信息密度高** —— 我们的用户来获取知识，不是来看视觉表演
- **无装饰糖** —— 没有 emoji 大量装点、没有夸张配色、没有插画填充空白
- **专业感** —— 用户是医学学习者，对严肃感敏感；不要"二次元"、"萌系"、"卡通"
- **数据可视化** —— 状态、强度、网络结构需要清晰可读，不是抽象艺术

### 排版

- 中文主体，思源宋体或思源黑体（开源，可选）
- 题目和讲解的字号要足够大（医学学习者长时间阅读）
- 行高 1.6-1.8，段间距充分
- 表格密度要高（模板字段都用表格呈现）

### 配色（建议方向，可改）

主色调：低饱和、专业。可考虑：
- 深灰 / 接近黑的主文字
- 蓝绿色系（医学传统但不老土）
- 暖橙色作为衰减状态预警色（不是红色——红色太刺激）

避免：纯黑（刺眼）、纯白（眩光）、亮红（医学场景下歧义）、霓虹色。

### 暗色模式

不是 MVP 必须，但 schema 设计时给暗色留接口。

### 移动端

PWA 响应式优先。设计师需要交付桌面 + 手机两套视觉稿。手机端用户场景：碎片时间复习。

## 状态可视化系统（强约束 · 设计师不能改）

四档状态出现在主页、节点页、地图、所有节点引用处。**形状 + 颜色双重编码**，色盲友好。

| 状态 | 符号 | 颜色定位 | 含义 |
|---|---|---|---|
| 未学 | ○ | 灰 (gray-400) | 从未访问 |
| 学过 | ● | 蓝 (sky-500) | 访问且 strength ≥ 60 |
| 熟练 | ● | 绿 (emerald-500) | strength ≥ 85 + 3 次成功检索 |
| 衰减中 | ●⚠ | 橙 (amber-500) | 曾达到 学过/熟练，现 strength < 60 |

**具体色值由设计师定**，但要符合：
- 4 个颜色明显可区分（不要相邻色相）
- 在浅色和深色背景上都清晰可读
- 不是高饱和（避免视觉疲劳）
- 衰减色用暖色（橙/琥珀），不用红色

形状可调整（○ ● 可换成实心/空心方块、圆圈、其他几何形），但必须形状 + 颜色都能独立辨识。

详细使用场景见 [`../02-features/F02-memory-strength.md`](../02-features/F02-memory-strength.md)。

## 关键 User Flows

设计师需要为这 4 条主路径出稿（详见各功能文档）：

### Flow A · 首次进入（未登录）
```
落地页（产品介绍）→ 注册（Email magic link）→ 主页（空状态）
                                                  ↓
                              引导：建议从 [[阴阳]] 开始（不强制）
```

### Flow B · 学习新节点（核心场景，最高优先级）
```
主页 → 点击节点 → 节点页（看讲解）→ 点测试 → 答题流（5 题）→ 反馈
                       ↑                                          ↓
                       └────── 回到节点（看强度变化）──────────────┘
```

### Flow C · 定向复习（用户主动）
```
主页 → 扫到衰减中节点 → 点节点 → 节点页 → 测试自己 → 强度回升
```

### Flow D · 状态查询（碎片时间）
```
主页 → 浏览大纲 → 想知道某节点状态 → 点开 → 看强度/最近答题
```

详细 wireframe（文字版）在 [`../02-features/F01-node-page.md`](../02-features/F01-node-page.md) 和 [`../02-features/F04-knowledge-map.md`](../02-features/F04-knowledge-map.md)。

## 题型设计要点

7 种题型，详见 [`../02-features/F03-question-types.md`](../02-features/F03-question-types.md)：

1. **single_choice** —— 最常见，但不要做主力
2. **multiple_choice** —— 选项要明显可勾选
3. **fill_in_blank** —— 输入框要大，键盘友好
4. **match** —— 拖拽 / 连线，移动端要可触控
5. **sort** —— 拖拽排序
6. **spell** —— 中文输入支持，容错友好
7. **derive** —— 自由文本，提交后显示参考答案 + 自评

**反馈三件套（必须）**：
- 即时正误指示（< 100ms）
- 正确答案显示
- "Why?" 解析（始终可点）

**绝不显示**："答对率 X%"、"得了 N 分"、"剩余时间"。

## 技术约束（你不决定但要知道）

- **Web 优先**：先做响应式 web，不做原生 app
- **PWA**：可安装到桌面，离线状态仅查看已学内容
- **首屏 < 1.5s**：节点页 TTI 不能慢
- **答题反馈 < 100ms**：本地计算，无网络依赖
- **包大小 < 200KB gzip**：图片资源要克制
- **暗色模式**：MVP 不必须，但设计变量结构要支持
- **国际化**：MVP 仅中文，UI 字符串与组件解耦

- 是「节点」不是「卡片」/「关卡」
