# 信息架构（5 层知识结构）

> 把碎片资料重构为「**少量公理 + 实体属性 + 推导规则 + 事实标签 + 应用路径**」5 层结构。这是整个产品的知识骨架。

## Why

直接把原始资料的题目按"单选/多选/简答"分类，是按题目属性组织，不是按知识属性。结果是：用户在做题时不知道这道题考的是哪个概念、概念之间什么关系、自己掌握了哪些。

5 层架构把同一份内容**从"题目集合"重组为"概念网络"**，并让每一层匹配一种最有效的学习模式。

## 5 层结构

```
┌──────────────────────────────────────────────────────────┐
│  L1  世界观层      公理性原理                  ~5 个节点  │
│                    阴阳、五行、整体观、辨证论治             │
│                    学习模式：沉浸式讲解 + 反复回炉          │
├──────────────────────────────────────────────────────────┤
│  L2  实体层        基本概念实体                ~40 个节点 │
│                    五脏六腑、气血津液、六淫七情、经络       │
│                    学习模式：模板填空 + 矩阵记忆            │
├──────────────────────────────────────────────────────────┤
│  L3  关系层        实体间的连接                ~50 条边   │
│                    相生相克、相表里、精血同源、配伍七情     │
│                    学习模式：推导题 + 图谱探索              │
├──────────────────────────────────────────────────────────┤
│  L4  事实层        具体标签型知识              ~500 节点  │
│                    要药标签、要穴主治、方剂组成、舌脉对应   │
│                    学习模式：SRS 卡片 + 多题型             │
├──────────────────────────────────────────────────────────┤
│  L5  应用层        综合推理                    ~30 条路径 │
│                    病→证→方 推理链、病案分析                │
│                    学习模式：场景化推理 + 综合题            │
└──────────────────────────────────────────────────────────┘
```

## 每层的设计意图

### L1 世界观
- 不是"要记的点"，是「中医的操作系统」
- 学好 L1 后，L2-L4 的大量内容可以被理解而非记忆
- 数量极少（~5 个），但反复出现在所有上层节点的解释中

**例**：阴阳互根 → 解释了气与血的关系、心与肾的关系、表里关系…

### L2 实体
- 高 ROI 投入区
- 每个实体有标准化的**模板**（详见下文），不同实体填不同的值
- 模板让 30%+ 的选择题（"X 的在液是？"、"Y 的开窍是？"）变成"在网格里查值"

### L3 关系
- 大部分关系可从 L1 + L2 推导，而不需要单独记忆
- 例：肺与脾的关系 = 五行（土生金）+ 各自功能 → 表现为"气的生成"和"津液代谢"
- 学习模式应该是「推一遍」而非「背一遍」

### L4 事实
- 真正需要硬记的部分（但比想象的少）
- 多数有"内在线索"可以精加工
- 这一层是 SRS 卡片的主战场

### L5 应用
- 综合 L1-L4 的能力检验
- 类似考试的"案例分析题"
- MVP 阶段不重点投入，先把 L1-L4 跑通

## 节点的粒度规则

**单一节点 = 一个最小可学习的概念。**

### 粒度判定的经验法则
- 一个节点的「讲解 + 检索测试」总时长 ≤ 10 分钟
- 一个节点的核心信息能被一段 200 字内的文字 + 一张表 覆盖
- 一个节点的所有事实可以挂 ≤ 20 道题
- 太粗就拆，太细就合

### 案例

| 概念 | 是否独立节点 | 理由 |
|---|---|---|
| 肝 | ✅ 是 | L2 实体，模板属性 + 功能 + 病证关联 |
| 肝阳上亢 | ✅ 是 | L4 证型，独立的辨证依据 |
| 肝在志为怒 | ❌ 否 | 是「肝」节点模板中的一个字段 |
| 肝主疏泄的 5 个功能 | ❌ 否 | 是「肝」节点内部展开的子章节 |
| 肝肾同源 | ✅ 是 | L3 关系节点 |
| 茵陈 | ✅ 是 | L4 单味药节点 |
| 茵陈蒿汤 | ✅ 是 | L4 方剂节点（与单味药节点不同） |

## 节点间的关系类型

边（Relation）的预定义类型集（其他类型应避免引入，否则维护成本爆炸）：

| 类型 | 含义 | 例 |
|---|---|---|
| `belongs_to` | 父子结构（脏腑→心） | 心 belongs_to 五脏 |
| `paired_with` | 表里 | 心 paired_with 小肠 |
| `generates` | 五行相生 | 木 generates 火 |
| `restrains` | 五行相克 | 木 restrains 土 |
| `prerequisite_for` | 学习前置 | 阴阳 prerequisite_for 八纲 |
| `related_to` | 弱关联（自由链接） | 黄疸 related_to 茵陈 |
| `treats` | 药/方→证 | 茵陈蒿汤 treats 阳黄 |
| `manifests_as` | 证→症状 | 心火亢盛 manifests_as 心烦失眠 |

**约束**：每条边必须是有类型的。禁止"无标签的连接"——会让图谱失去可解释性。

## 模板（Template）系统

L2 实体节点必须有「模板」属性。模板是 schema，不是内容。

### 已定义模板

#### 五脏模板
```yaml
五行: <木|火|土|金|水>
在志: <怒|喜|思|悲|恐 或派生>
在液: <泪|汗|涎|涕|唾>
在体: <筋|脉|肌肉|皮|骨>
其华: <爪|面|唇|毛|发>
开窍: <目|舌|口|鼻|耳及二阴>
表里腑: <胆|小肠|胃|大肠|膀胱>
通应季节: <春|夏|长夏|秋|冬>
```

#### 六淫模板
```yaml
阴阳属性: <阴|阳>
核心性质: [<性质 1>, <性质 2>, ...]  # 2-4 条
典型症状: [<症状 1>, ...]
易伤脏腑: [<脏 1>, ...]
```

#### 单味药模板
```yaml
四气: <寒|热|温|凉|平>
五味: [<辛|甘|酸|苦|咸 中一个或多个>]
归经: [<经名>]
核心功效: [<功效 1>, ...]
要药标签: <可选，X 要药>
```

#### 方剂模板
```yaml
组成: [<药 1>, <药 2>, ...]
君药: <药名>
功效: [<功效 1>, ...]
主治: <证名>
所属类别: <如"清热剂">
```

**新增模板的规则**：当某类节点 ≥ 5 个且共享至少 4 个属性时，定义新模板。否则用自由格式。

## 与原始资料的映射

原始资料（中医.docx，1730 行，~440 题）的内容如何映射到 5 层：

| 资料中的内容 | 映射到 |
|---|---|
| "131. 中医最主要特点：整体观念、辨证论治" | L1 节点 |
| "208. 五脏的特点：心..." | 5 个 L2 节点（每脏一个） |
| "80. 六淫的性质和致病特点" | 6 个 L2 节点 + L1 公理 |
| "81. 脏腑之间的关系，考了肝和肾" | 多个 L3 关系节点 |
| "228. 浙贝母和川贝母的区别" | 2 个 L4 节点 + 对比页 |
| "240. 麻黄汤..." | 1 个 L4 方剂节点 |
| "10. 临床中医学各种证对应的方剂" | 多条 L5 推理链 |

详细映射在 [`../03-content/node-catalog.md`](../03-content/node-catalog.md)。
