# 节点清单（MVP）

> MVP 阶段的 30 个核心节点。每行追踪：层 / 类别 / 状态 / 题目数 / 数据源。这是内容工程的进度看板。

## Why

节点不是抽象规划，必须落到具体清单。这份文档让任何时刻都能回答：「目前哪些节点已完成？哪些还在草稿？覆盖率多少？」

---

## 状态图例

| 符号 | 状态 | 含义 |
|---|---|---|
| ⬜ | 未做 | 还没开始 |
| 🟨 | generated | LLM 已生成草稿，等审校 |
| 🟦 | reviewed | 人审通过，可上线 |
| 🟩 | live | 已部署，用户可见 |
| 🟥 | rejected | 被否决，需要重做 |

## 覆盖度估算

30 节点能覆盖原资料的题目比例（粗估）：

| 节点群 | 数量 | 覆盖题目数（估） |
|---|---|---|
| 五脏 + 六腑 | 8 | ~120 题 |
| 六淫 | 6 | ~30 题 |
| 八纲 | 2 | ~25 题 |
| 气血津液 | 3 | ~25 题 |
| L1 公理 | 4 | ~30 题 |
| 关系 + 要药 + 穴 | 7 | ~30 题 |
| **合计** | **30** | **~260 / ~440 ≈ 60%** |

MVP 之后再补 30 个节点（方剂、舌脉、辨证细节），可达 90%。

## Open Questions

- [ ] 30 个 MVP 节点是否过多/过少？过多会拖延 MVP，过少覆盖率不足。可以分两批，先做 15 个跑通流程，再做 15 个。
- [ ] 「八纲辨证」是 1 个节点还是 8 个节点（每个证型一个）？目前放 2 个（总论 + 综合），观察用户反馈再调整。
- [ ] 要药要不要全 30+ 个一次做完？还是先做 4 个示范？倾向于先做 4 个跑流程，再批量。
