# ADR-004 · 用 Email Magic Link 作为认证方式

## Context

需要给用户一个账户系统，让每个人独立记录学习进度。MVP 阶段的认证方式选择影响：

1. **用户首次体验**：摩擦越低留存越好
2. **隐私边界**：用户愿意给我们多少信息
3. **工程复杂度**：自建认证 vs 第三方
4. **跨设备同步**：用户在手机/桌面间切换的体验
5. **目标用户群覆盖**：中国大陆用户场景

可选方案：

| 方案 | 特点 |
|---|---|
| 邮箱密码 | 传统，用户最熟悉 |
| Email magic link | 无密码，一次性登录链接 |
| GitHub OAuth | 技术用户友好 |
| Google OAuth | 海外主流，中国用户访问受限 |
| 微信 OAuth | 中国主流，但需企业资质 |
| Apple Sign in | iOS 用户友好，但 App Store 强制要求 |
| 手机号 + 短信 | 中国主流，但短信成本 + 资质门槛 |
| Anonymous（仅本地） | 无注册，纯本地存储 |

---

## Decision

**MVP 默认使用 Email Magic Link，作为唯一登录方式。**

### 具体设计

- 用户输入邮箱 → 我们发一封带一次性登录链接的邮件
- 用户点链接 → 登录成功，session 建立
- Session 长期保持（30 天），用户少需要重新登录
- 不要求邮箱"激活"——首次输入即认证
- 不存储密码——表里没有 password 字段
- 邮件服务用 Resend / Postmark（开发期免费额度足够）

### 不做

- ❌ 邮箱密码登录
- ❌ 任何 OAuth（GitHub/Google/微信/Apple）—— MVP 后再加
- ❌ 短信验证 —— 成本和资质都贵
- ❌ 注册时填昵称/资料 —— 用户初体验越简单越好，邮箱即唯一标识

---

## Consequences

### 好的

- **摩擦极低**：用户输入邮箱 → 点邮件链接 → 进 app。比注册流程少 3-5 步
- **无密码管理负担**：用户不用记密码、找回密码；我们不用做密码强度策略、加密存储
- **安全性高**：没有密码 = 没有撞库风险；magic link 短期失效
- **隐私友好**：我们只知道用户的邮箱，不知道任何其他信息（与"工具非习惯"对齐——尊重用户）
- **工程简单**：Auth.js 内置 Email Provider，开箱即用
- **跨设备无缝**：在新设备上输邮箱再点链接即可

### 坏的 / 取舍

- **依赖邮箱**：用户必须能收邮件——但今天几乎所有目标用户都有邮箱
- **email 送达问题**：某些邮箱服务（特别是中国某些企业邮箱）可能把链接邮件归到垃圾箱
  - 缓解：用 Resend 这种声誉好的发送方
  - 缓解：在落地页提示"请检查垃圾邮件"
- **没有"快速切换账号"**：每次切都要重新点邮件链接
  - 缓解：MVP 阶段一个人只用一个账号是常态
- **不能直接用 GitHub commit author 关联**：技术用户可能希望 GitHub OAuth 一键登录
  - 缓解：MVP 之后加 OAuth 作为可选项（关联到同一账户）

### 中性

- 用户的 email 是唯一标识——更换邮箱需要单独流程
- 不收集姓名/头像等信息——节点页/主页不会显示用户头像（与"工具"定位对齐，无社交需求）

## Alternatives Considered

### 方案 A：邮箱 + 密码
- 优点：用户熟悉
- 缺点：
  - 需要密码强度策略
  - 需要"忘记密码"流程
  - 增加用户摩擦（"又一个网站要记密码"）
  - 我们成为密码泄漏的潜在源头
- **否决**：MVP 不值得这个复杂度

### 方案 B：仅 GitHub OAuth
- 优点：一键登录、技术用户友好
- 缺点：
  - 非技术用户（医学院学生）多数没 GitHub 账号
  - 强迫用户暴露 GitHub profile 给我们
  - 排除大量目标用户
- **否决**：与目标用户群不匹配

### 方案 C：仅 Google OAuth
- 优点：海外通用
- 缺点：
  - 中国大陆用户访问困难
  - Chrome 浏览器外的体验降级
  - GFW 风险
- **否决**：中国用户友好性差

### 方案 D：微信 OAuth
- 优点：中国主流
- 缺点：
  - 需要企业资质、ICP 备案
  - 个人开发者无法直接接入（要绕开放平台中间商）
  - 桌面端体验差（需要扫码）
  - 与"严肃工具"调性不匹配（微信生态偏社交）
- **否决**：MVP 阶段资质门槛太高

### 方案 E：手机号 + 短信
- 优点：中国用户熟悉
- 缺点：
  - 短信成本约 0.05 元/条，规模化后是固定成本
  - 需要短信服务商资质（实名认证、模板审核）
  - 手机号是隐私敏感信息，存储要更高合规要求
- **否决**：成本和合规都贵

### 方案 F：纯匿名（本地存储进度）
- 优点：零摩擦、零隐私问题
- 缺点：
  - 无法跨设备
  - 清缓存就丢数据
  - 没有用户分层和反馈通道
- **否决**：违背用户独立记录的需求

### 方案 G（采用）：Email Magic Link
- 平衡了摩擦、安全、隐私、覆盖面
- Auth.js 一行配置即可

### 方案 H（MVP 后）：Magic Link + OAuth 混合
- 主路径是 Magic Link
- 增加 GitHub/Google 作为"快速登录"可选项
- 已有账号的用户可以绑定多种登录方式
- **暂缓**：MVP 后再加，等到用户反馈"想用 GitHub 登录"

## 实施细节

### 邮件服务选择

| 服务 | 免费额度 | 中国送达 | 备注 |
|---|---|---|---|
| Resend | 100/天 | 良好 | 现代 API，推荐 |
| Postmark | 100/月 | 良好 | 老牌可靠 |
| SendGrid | 100/天 | 良好 | 巨头但配置复杂 |
| AWS SES | 200/天 | 良好但需配置 | 价格便宜，规模化用 |

**MVP 用 Resend**。规模超出免费额度后切 AWS SES。

### 链接有效期

- Magic link 有效期：**15 分钟**
- 使用一次后立即失效
- Session 时长：**30 天**（无活动则过期）

### 退出登录

- 仅清除当前设备 session
- "所有设备退出"作为高级选项（设置页）

### 用户没收到邮件怎么办

- 提示检查垃圾邮件
- "重新发送"按钮（每分钟限 1 次）
- 客服邮箱兜底（人工帮助）
