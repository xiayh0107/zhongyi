# ADR-001 · 工具而非习惯机器

## Context

学习类 app 在过去十年形成了一套主流打法（多邻国是范例）：游戏化、daily streak、push 通知、徽章等级——本质是"习惯机器"。这套机制确实做出了亿级用户的产品。

我们要做中医学习 app，是否沿用这套打法？

### 中医学习者的真实场景

观察用户群（应试者、临床执业者、兴趣学习者、转行者）：

| 用户群 | 动机来源 | 时间投入特点 |
|---|---|---|
| 应试者 | 考试压力 | 集中冲刺，考后即停 |
| 临床执业者 | 工作刚需 | 碎片时间，按需查询 |
| 兴趣学习者 | 内在好奇 | 节奏松散，但持续 |
| 转行者 | 学习目标 | 集中突击 + 长期巩固 |

**共同点**：他们都**自带动机**。没人需要 app 哄他们坐下来。

### 习惯机器的代价

游戏化机制不是免费的。它带来：

1. **稀释严肃感**：医学学习者对"勋章、皮肤、连胜火苗"普遍反感
2. **指标错位**：DAU 和留存成为成功指标 → 产品决策被迫服务"让用户回来"，而非"让用户学会"
3. **挫败感放大**：错过 daily streak 的用户会有"我又失败了"的情绪，反而离开
4. **假学习**：用户为了 streak 应付几分钟点击，没有真正检索练习

### 关键观察

多邻国成功的核心**不是**游戏化，而是：
- **可信的语言学习数据库**（牛津、剑桥级内容）
- **科学的间隔重复**（虽然不是最优算法）
- **极低的入门摩擦**

游戏化只是它服务"零基础语言学习者"群体的**适配**。我们的用户群体不同，适配也应不同。

---

## Decision

**Fast Memory 是工具，不是习惯机器。**

具体含义：

1. 没有 daily streak、连续打卡、勋章、等级、皮肤、排行榜
2. 没有 daily goal、今日任务、完成度百分比
3. 不主动 push 催回（除用户显式订阅提醒）
4. 北极星指标是"用户达成目标的速度 + 需要时能回来"，不是 DAU
5. 用户考完不回来是**产品成功**的一种表现，不是流失

---

## Consequences

### 好的

- **设计聚焦**：所有功能讨论都有"这是为目标达成还是为日活"的清晰判据
- **避免反模式**：游戏化反过来稀释产品严肃感的陷阱被屏蔽
- **匹配用户**：自带动机的用户感到"被尊重"，而非"被哄"
- **简化产品**：少做大量游戏化功能（积分系统、徽章系统、社交系统）

### 坏的 / 取舍

- **增长曲线可能慢**：没有 push、没有 streak 的产品，自然增长依赖纯粹的口碑和搜索
- **难以做"用户分层"**：游戏化 app 可以靠新手关把零基础留住，我们必须从一开始用内容质量留住
- **VC 故事不性感**：DAU 数字增长慢，融资叙事比"下一个多邻国"难讲
- **如果某些群体确实需要外部激励呢**：（比如自律差的考生）—— 我们承认这是损失，但不为这部分人改变方向

### 中性

- 产品成功的衡量需要重新定义（北极星指标 = "5 分钟内开始有效检索练习"）
- 团队招聘时需要明确这个方向，避免拉来习惯机器的人才不适应

## Alternatives Considered

### 方案 A：完整套用多邻国打法
- streak、徽章、等级一应俱全
- 优点：成熟、被验证、增长快
- **否决**：与用户群体不匹配，会导致严肃用户流失（医学学习者敏感度高）

### 方案 B：折中——只用 streak 和进度可视化，不用徽章等级
- 看起来"温和的游戏化"
- **否决**：streak 是核心反模式（强加日节奏），单独保留不能解决问题。要么不做，要么全做。

### 方案 C：让用户自选模式（游戏化 / 工具）
- 设置面板里切换
- **否决**：双向维护成本太高，且大多数用户不会调设置。默认值决定一切，必须先选一个默认。

### 方案 D：分两个版本（应试版工具，兴趣版游戏化）
- **否决**：MVP 阶段不分版本，资源不够；况且两类用户重叠（兴趣学习者也会去考证）
