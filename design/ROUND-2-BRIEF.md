# Design · 第二轮任务简报

> 给设计团队的第二轮工作清单。**只补 A 变体**（变体决策见 [`../docs/04-decisions/ADR-005-variant-a-as-mvp.md`](../docs/04-decisions/ADR-005-variant-a-as-mvp.md)）。

## 背景与目的

首轮交付（[`README.md`](README.md) + [`REVIEW.md`](REVIEW.md)）已完成 F01/F03/F04 三个核心页面。开发即将进入 **M1**——但 M1 有几个页面/状态首轮没覆盖，需要你补齐才能完整跑通用户首次登录到答题闭环的全链路。

第二轮任务**全部基于 A 变体**——不再做 B 变体。tokens、组件、字体保持不变。

---

## 总体约束（与首轮相同）

1. **严格沿用 A 变体的 tokens** — `tokens.jsx` 里 `TOKENS.A`，**不要新增颜色 / 字体 / 间距**
2. **直接复用首轮组件** — `StatusBar` / `TierDot` / `PrimaryBtn` / `SecondaryBtn` / `GhostBtn` / `LinkBtn` / `NodeCard` / `WikiLink`（在 `tokens.jsx` 和 `design-system.jsx` 里）
3. **反模式清单全部仍然有效** — 12 项一个都不能违反，详见 [`../docs/_meta/design-brief.md`](../docs/_meta/design-brief.md)
4. **6 条设计原则全部仍然有效** — 详见 [`../docs/00-vision/design-principles.md`](../docs/00-vision/design-principles.md)

新增的强约束：
- 5. **所有错误/空/loading 态都要避免"过度安抚"** — 不写"别担心，马上好"这种空话；告诉用户**发生了什么 + 能做什么**
- 6. **网络/服务相关的等待要诚实** — 不要假装"正在思考"等暗示 AI 在工作的话术；这是工具

## P0 任务详细说明

### F00-1 · 登录入口页

**路径**：`/login`

**用户行为**：未登录用户访问任何需要登录的页面时被重定向到这里；或主动从主页右上角"登录"进入。

**核心动作**：输入邮箱 → 点"发送登录链接" → 跳到 F00-2 检查邮箱页。

**文字版 wireframe（桌面）**：

```
┌─────────────────────────────────────────────┐
│  ← 返回                            Fast Memory │
│                                                │
│                                                │
│                                                │
│              # 登录 Fast Memory                 │
│              用邮箱获取一次性登录链接              │
│                                                │
│              ┌──────────────────────────┐      │
│              │  your@email.com          │      │
│              └──────────────────────────┘      │
│                                                │
│              [  发送登录链接  ]                  │
│                                                │
│              ─────────────────────────         │
│              无需密码 · 无需注册                  │
│              首次输入即开通账户                   │
│                                                │
│              我们仅使用邮箱识别你·               │
│              不会发送任何营销邮件                 │
│                                                │
└─────────────────────────────────────────────┘
```

**关键文案**：
- 标题用宋体（H1, 思源宋 32-36px）
- 副标题用黑体 (Body, 14px)
- "无需密码 · 无需注册"是反直觉信任建立——这套话术不能动
- "我们仅使用邮箱识别你..." 是隐私承诺——是认证策略的核心信任锚点

**状态分支**：
- 默认态（空输入框）
- 用户输入中
- 邮箱格式错误：输入框下方红字提示"邮箱格式不正确"（不要弹窗）
- 提交中：按钮变 disabled + 文字变"发送中..."
- 速率限制：按钮变 disabled + 提示"60 秒后可重新发送"

**移动端**：单列居中，输入框和按钮全宽。

### F00-2 · 检查邮箱页

**路径**：`/login/check-email`

**目的**：让用户安心等邮件。这里不能让用户觉得"卡住了"。

**文字版 wireframe**：

```
┌─────────────────────────────────────────────┐
│                                                │
│              # 邮件已发送                       │
│                                                │
│              我们刚发了一封登录邮件到             │
│              ┌──────────────────────────┐      │
│              │  your@email.com          │      │
│              └──────────────────────────┘      │
│                                                │
│              点击邮件中的链接即可登录·           │
│              链接 15 分钟内有效                   │
│                                                │
│              ────────────────────────          │
│                                                │
│              · 没收到？请检查垃圾邮件              │
│              · 邮箱地址错了？  [换邮箱]         │
│              · 60 秒后可以  [重新发送]          │
│                                                │
└─────────────────────────────────────────────┘
```

**关键文案**：
- 用户邮箱要显示出来（确认我们发到正确地址）
- 三条提示按重要性排序：先指引检查垃圾邮件，再换邮箱，最后重发
- "60 秒后可以"——前 60 秒按钮 disabled 带倒计时；之后可点击

**反模式**：
- ❌ 不要旋转加载图标——邮件已经发出，没在加载
- ❌ 不要"我们正在为您..."这种营销话术——就告诉用户已发出，等待是用户的事
- ❌ 不要倒计时压力（"剩余时间 14:59"）——只在 60 秒内重发按钮做倒计时即可

### F00-3 · 登录失败 / 链接过期页

**路径**：`/login/error?reason=expired` 或 `?reason=invalid` 或 `?reason=used`

**触发**：用户点击 magic link，但 token 过期、无效、已使用。

**文字版 wireframe**：

```
┌─────────────────────────────────────────────┐
│                                                │
│              # 登录链接无法使用                  │
│                                                │
│              这个链接 [已过期 | 无效 | 已使用]    │
│              链接只能使用一次·只有 15 分钟有效   │
│                                                │
│              [  重新发送登录链接  ]               │
│                                                │
│              或  [换个邮箱]                      │
│                                                │
└─────────────────────────────────────────────┘
```

**三种 reason 的副本**：
- `expired`：「这个链接已过期。链接只能使用一次·只有 15 分钟有效」
- `invalid`：「这个链接无效。可能是邮件客户端改写了链接，或链接已被使用」
- `used`：「这个链接已经用过了。请重新发送新链接」

**关键**：直接告诉用户**发生了什么 + 能做什么**，不要绕弯。

### F00-4 · Email HTML 模板

**用途**：用户输入邮箱后收到的登录邮件。

**约束**：
- HTML 邮件兼容性差，**只能用 inline style + 简单 table 布局**
- 不能用 web font（用 system fallback）
- 必须在 Gmail / Outlook / Apple Mail / QQ 邮箱里都能正常显示
- 暗色模式适配（很多邮件客户端默认暗色）

**文字版 wireframe**：

```
┌─────────────────────────────────────────┐
│                                          │
│  Fast Memory                             │
│                                          │
│  # 登录 Fast Memory                       │
│                                          │
│  点击下方按钮登录：                       │
│                                          │
│  ┌────────────────────────┐             │
│  │    登录                 │             │
│  └────────────────────────┘             │
│                                          │
│  按钮无效？复制下面链接到浏览器：           │
│  https://app.fast-memory.com/auth/...    │
│                                          │
│  ─────────────────────────────           │
│                                          │
│  链接 15 分钟内有效·只能使用一次          │
│  如果不是你本人操作，请忽略此邮件          │
│                                          │
└─────────────────────────────────────────┘
```

**关键设计**：
- 极简——一个标题、一句话、一个按钮、一个 fallback 链接
- 按钮要够大（触控友好 ≥ 44pt 高度）
- 链接 fallback 必须有——按钮有时不工作

**交付**：HTML + inline CSS 字符串。我们用这个字符串调 Resend API。

### 空状态系列

#### 未登录用户访问主页

**触发**：未登录用户访问 `/`。

**两个选择**：
- **A 方案**：跳转到 `/login`
- **B 方案**：显示一个落地页（介绍产品 + 登录入口）

**决策**：暂用 A 方案（最简）。如果你强烈建议做落地页（更友好），写个 mockup 我评估。

如果做落地页，要素：
- 一句话定位「把碎片资料重构为可点亮知识网络的快速学习工具」
- 一张产品截图（节点页或主页）
- 一个"登录 / 开始使用"按钮
- 不做产品功能详述（用过才知道）

**触发**：节点存在但暂时没有题目（理论上不应该有，但要兜底）。


无需独立页面，节点页里的状态变化即可。

### 加载态系列

#### 节点页加载

**触发**：用户点击节点链接，等待节点内容加载。

**约束**：
- TTI < 1.5s（首屏目标）—— 大部分时候用户不会看到加载态
- 即便如此也要有兜底

**建议方案**：**Skeleton screen**，不要 spinner。

骨架的字段对应节点页结构：
- 面包屑（一行短灰条）
- 标题（一行长灰条）
- summary（半行灰条）
- template 表（8 行 x 2 列灰条）
- body 标题 + 段落（不规则灰条）

灰条用 `T.line` 色，pulse 动画 1.2 秒一次（subtle）。

#### 题目流加载

**触发**：从节点页点"测试自己"，等待题目集加载。

**约束**：题目通常瞬间加载完——除非网络慢。

**建议**：跟节点页同款 skeleton，但更小（一个题干灰条 + 几个选项灰条）。

#### 邮件发送中

**触发**：F00-1 用户点"发送登录链接"后。

按钮文字 → "发送中..."，按钮 disabled。**不要全屏 loading**。

## 共用规范

### 排版

- 标题：思源宋 H1 32-36px / H2 22-26px
- 正文：思源黑 16px / line-height 1.7
- meta / 数字：JetBrains Mono 11-12px

### 颜色（A 变体 token 引用）

只用以下 token，不要新增颜色：
- 文字：`ink` / `ink2` / `ink3`
- 背景：`bg` / `paper` / `sheet`
- 分割线：`line` / `line2`
- 强调：`accent`（松绿）—— 仅用于 CTA / 焦点
- 状态：`s_untouched` / `s_learned` / `s_mastered` / `s_fading`

### 按钮使用规则

- `PrimaryBtn`：每页最多一个，最重要的下一步动作
- `SecondaryBtn`：次要可选动作
- `GhostBtn`：放弃 / 跳过 / 退出（低调）
- `LinkBtn`：内联文字操作（"Why?" 等）

### 留白

- 桌面：内容容器最大宽 820px（阅读舒适）
- 移动端：左右各 20px 边距

### 错误 / 状态文案的语气

| ❌ 别这么写 | ✅ 这样写 |
|---|---|
| "出错了，请稍后再试" | "服务器暂时无法响应。点 [重试] 或几分钟后回来" |
| "你的网络似乎有点问题" | "你似乎离线了。已学过的节点可以继续浏览" |
| "正在为您加载，请稍候..." | "加载中…"（或直接 skeleton） |
| "登录成功！欢迎回来！🎉" | 默默跳转到主页，无 toast |
| "嗯哼，我们正在思考" | 不存在——我们不思考，是程序在响应 |
